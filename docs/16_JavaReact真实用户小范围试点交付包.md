# 16 · Java + React 重构版真实用户小范围试点交付包

> 日期：2026-07-07
> 适用范围：`rebuild/` Java Spring Boot + React 重构版
> 结论：当前目标是**真实用户小范围试点**，不是生产上线。

## 1. 试点目标

本次试点验证四类角色是否能用真实数据完成招聘主流程：

- 招聘专员能上传简历、管理候选人、加入流程、推进候选人、安排面试。
- 招聘经理/负责人能看岗位进展、候选人归属、招聘专员绩效提示和流程卡点。
- 面试官能查看自己的面试、候选人材料和反馈边界。
- 管理员能创建/启停/重置账号，并查看系统设置里的系统治理和审计 demo 边界。

试点负责人执行部署、环境变量、账号、冒烟和备份恢复演练时，以 [17 · Java + React 真实试点前落地准备清单](./17_JavaReact真实试点前落地准备清单.md) 为准。

## 2. 账号和角色

真实试点不使用固定 demo 账号。账号由管理员在“用户治理”中创建。

首次管理员创建方式：

1. 运维临时配置 `PILOT_BOOTSTRAP_ADMIN_EMAIL` 和 `PILOT_BOOTSTRAP_ADMIN_PASSWORD`。
2. 管理员首次登录。
3. 管理员创建招聘专员、负责人、面试官账号。
4. 运维删除 bootstrap 环境变量并重启后端。
5. 管理员给试点人员分发各自账号。

角色建议：

| 角色 | 建议人数 | 主要入口 |
|---|---:|---|
| 招聘专员 | 1-3 | 工作台、上传简历、简历库、候选人流程、面试任务 |
| 招聘经理/负责人 | 1 | 工作台、招聘管理、候选人流程、数据看板 |
| 面试官 | 1-3 | 工作台、我的面试 |
| 管理员 | 1 | 用户治理、系统设置 |

## 3. 主流程

招聘专员：

1. 登录后进入工作台。
2. 在“上传简历”上传真实试点简历。
3. 到“简历库”确认解析后的候选人已入库。
4. 点击“加入流程”，选择有效岗位，进入 AI 初筛。
5. 到“候选人流程”查看候选人在各阶段的位置。
6. 到“面试任务”填写候选人 ID、岗位 ID、面试官账号 ID，安排面试草稿。

招聘经理/负责人：

1. 登录工作台查看团队看板提示。
2. 到“招聘管理”检查岗位是否仍有效。
3. 到“候选人流程”查看岗位进展和卡点。
4. 到“数据看板”查看团队口径提示。
5. 如果发现候选人负责人分错，记录问题并交给管理员/负责人手动修正。

面试官：

1. 登录后进入“我的面试”。
2. 只查看分配给自己的面试。
3. 查看候选人材料和反馈边界。
4. 如果没有看到面试，联系招聘专员确认是否安排到正确账号。

管理员：

1. 在“用户治理”创建、启停、重置试点账号。
2. 在“系统设置”查看 demo 参数和审计边界。
3. 不直接修改数据库；账号问题优先通过页面处理。

## 4. 已知限制

- 这不是生产上线，没有完整字段级加密、监控平台、生产审计中心和灾备演练报告。
- AI 助手、系统设置里的系统治理、通知待办仍有 demo / in-memory 边界。
- 面试安排当前填写 ID，不是可搜索选择器。
- 误推进可以去候选人流程看板查看历史并纠正。
- 误关闭岗位、误淘汰、负责人分错仍需负责人或管理员记录后手动补救。
- Java rebuild 当前没有 `FIELD_ENCRYPTION_KEY` 字段级加密能力，不能把它当成已上线安全能力。

## 5. 不要做的危险操作

- 不要在真实试点库运行 `dev` profile 或任何 seed/reset 脚本。
- 不要使用 `demo.*@hireinsight.local` 固定演示账号录入真实简历。
- 不要把真实 `.env`、JWT 密钥、数据库密码截图或发到群里。
- 不要手工删除 PostgreSQL 表或上传目录。
- 不要把 `/tmp` 当作上传目录。
- 不要在没有备份的情况下批量导入、批量删除或恢复数据。

## 6. 反馈方式

每个试点问题按下面格式记录：

```text
时间：
角色：
账号：
页面：
操作步骤：
候选人/岗位/面试 ID：
期望结果：
实际结果：
截图或录屏：
是否可复现：
影响范围：
```

问题分级：

- P0：无法登录、数据库不可用、真实数据丢失或泄露风险。立刻停止试点并通知负责人。
- P1：主流程无法继续，例如无法上传、无法加入流程、无法安排面试。
- P2：提示不清楚、列表为空但不知道下一步、统计口径疑问。
- P3：文案、样式、体验优化。
