## 0. 结论速览

**技术主流程可运行，但尚未完成产品试点检查，不能对外承诺「可上线」或「已完善」。**

按 `AGENTS.md` 的三层判断：
- **技术可运行**：是。后端 268 个 `@Test`，前端 52 个静态契约测试；LLM / BOSS CLI / 字段加密三大核心均有真实实现（非纯桩）。
- **产品可试用**：部分。4 角色主路径有后端 + 前端页面，但前端 FE-1~FE-8 **无独立提交证据**，对接是否真实跑通存疑；文档与代码大面积不一致会误导试点。
- **生产可上线**：否。缺监控、灾备演练报告、字段加密在 pilot 默认未配 key、BOSS 默认 demo 模式。

**当前最大的系统性风险不是功能缺失，而是「文档落后于代码」造成的一致性危机**：5 份核心文档仍写 Vue 栈或残留 Vue 路径，2 份部署文档的前端路径错误，1 份端口测试与新配置矛盾，1 份 API 文档的边界标注停留在 BE 任务执行前。

## 2. 核对发现的不足（按严重度分级）

### CRITICAL — 阻塞试点 / 误导操作

#### C1. 部署文档前端路径错误，按此部署会失败
- `rebuild/DEPLOYMENT.md:11,60,98` 写 `rebuild/frontend`，**该目录不存在**（实际 React 前端在根 `frontend/`）。
- `docs/17:71,83` 部署命令写 `cd /srv/hireinsight/rebuild/frontend-vue`、Nginx root `rebuild/frontend-vue/dist`——**Vue 源码已在 `de19a46` 删除**。
- 影响：运维按清单部署会去构建已删除的目录，直接卡死试点上线。

#### C2. 3 份核心文档标题/正文仍写 Vue，与 React 实际栈矛盾
- `docs/15`（标题「Java Spring Boot + **Vue** 重构 MVP 状态报告」）、`docs/16`、`docs/17` 全文 Vue 叙事。
- `docs/15:10` 内部自相矛盾：同一段既写「Vue 入口」又写「GSAP 动画保留在 **React** 前端」。
- `rebuild/README.md:87-89` 三处文档链接指向**不存在的 React 命名文件**（实际文件名仍是 Vue）。
- 影响：试点负责人无法判断以哪份为准，技术栈认知混乱。

#### C3. 前端端口测试与配置矛盾，`npm test` 会失败
- `frontend/tests/dev_server_contract.test.mjs:6` 断言 proxy target 为 `http://localhost:5001`（旧 Flask 端口）。
- `frontend/vite.config.ts:16` 实际为 `http://localhost:8080`（Spring Boot，`261c803` 已改）。
- 影响：前端测试门禁失效；`commit 20a8a48` 声称「FE-1~FE-8 all 200」但若 `npm test` 跑不过则该冒烟结论存疑。

### HIGH — 严重影响质量与可维护性

#### H1. FE-1~FE-8 无独立提交证据，对接真实性存疑
- `docs/18` 列 FE-1~FE-8 共 8 个前端对接任务，git log 中**零提交**。
- React 前端页面文件早已存在（`docs/18` 称「React 已有，近乎即用」），但「页面存在」≠「与 BE-1~BE-7 新端点对接跑通」。
- BE-4 新增 7 个 BI 指标端点、BE-6 新增指南/调度接口、BE-3 新增 SSE `/agent/chat`——前端是否消费了这些新契约，未验证。
- 影响：无法证明前端富功能（BI 钻取、Agent 流式、面试 LLM 评分）真实可用。

#### H2. vitest 组件测试未接入构建门禁
- `frontend/src/` 下有 54 个 `.test.ts(x)`（vitest + jsdom），覆盖 agent/bi/candidate/pipeline 等组件。
- 但 `package.json` **未声明 vitest 为 devDependency**，无 `test:vitest` 脚本，`npm test` 只跑 `tests/*.mjs` 静态契约。
- `npm run build` 仅 `vite build`，**不含 typecheck**——类型错误不阻断构建。
- 影响：54 个组件测试形同虚设，全新安装环境 `npx vitest` 可能无法运行；类型回归无保护。

#### H3. Flyway 迁移脚本编号跳号（缺 V1–V4、V6–V8）
- `db/migration/` 仅有 V5、V9–V18，缺 V1–V4、V6–V8。
- 全新空库部署时这些早期表（users/jobs/candidates 等核心表）是否由 `ddl-auto` 补建，还是缺失，未验证。
- `docs/17:37` 称 pilot 用 `ddl-auto=validate` 不自动建表——**若 validate 模式下缺迁移脚本，空库会启动失败**。
- 影响：全新试点环境部署可能建表不全或启动报错。

#### H4. API.md 边界标注滞后，与 BE 实现矛盾
- `rebuild/backend-java/API.md:1204` 仍写「简历解析 JSON 内容暂为 `{}` 占位」——BE-1 已实现 LLM 解析。
- `API.md:1162` 标 Agent 会话「❌ 进程内存」——BE-3 已持久化（V16）。
- `API.md:1164` 标 BOSS「in-memory demo」——BE-2 已有 real 模式（默认 demo）。
- 影响：开发者/试点负责人误以为仍是桩，低估系统能力或误判边界。

### MEDIUM — 技术债与试点体验

#### M1. OfferController 缺入参校验与 service 层
- `offer/OfferController.java:46-62` 直接 `body.get("candidateId").toString()`，缺字段时 NPE；无 service 层，无测试。
- 影响：误操作或脏请求导致 500，无兜底提示。

#### M2. 根 RUNNING.md 仍是 Python Flask 栈
- `/RUNNING.md` 整篇 `cd backend && python run.py`，完全不提 Java+React。
- 影响：新接手者按此文档无法启动当前系统。

#### M3. rebuild/RUNNING.md 残留 Vue + Python 账号说法
- `rebuild/RUNNING.md:110` 写「新的 Java + **Vue** 本地试用请优先使用上表的 **Python 原版账号**」——双重过时（Vue 已删，Java 后端已自管账号）。

#### M4. rebuild/frontend-vue/ 磁盘残留构建缓存
- `.vite/`、`dist/`、`node_modules/` 三个未跟踪目录仍占盘，git 已不跟踪。
- 影响：磁盘混乱，易误以为 Vue 仍在。

#### M5. BOSS 默认 demo 模式 + 字段加密默认未配 key
- `app.boss.demo-mode=true`（AppConfig:93）、LLM `apiKey=""` 默认空、加密 dev 模式用临时 key。
- 这三者本身是合理的「安全降级」，但 **pilot 启动校验是否强制要求关闭 demo / 配真实 key**，未在 `PilotReadinessValidator` 验证。
- 影响：pilot 环境可能以 demo 模式静默运行，BOSS/AI/加密能力名不副实。

#### M6. 多 Controller 测试覆盖不足
- `OfferController`、`AiArchitectureController`、`notifications/NotificationController` 等较新模块无专门 controller 测试或覆盖薄。
- `LlmClientTest` 仅覆盖 mock 降级，未覆盖真实 HTTP 路径（合理但留有盲区）。
