# Java Spring Boot + Vue 重构版口径修正 PRD

> 日期：2026-07-07
> 目标：把前端页面、README 与说明文档里最容易误导协作者的几处口径收口到同一套事实。

## 1. 这次要修正的试点缺口

1. `AdminUsersView` 不能再被写成只有 `list / toggle`。
2. `CandidateListView` 不能再写“异步解析还没真实入库”。
3. API 文档需要把 AI 助手限定为进程内存 demo 会话与 confirm-first 消息接口。
4. `revert-lite`、`Offer / Onboard / Reject` 的 demo-only 边界要写清楚。
5. 集成账号、扩展上下文、抓取任务只能描述为非真实第三方 demo 壳层。
6. 招聘专员缺少从候选人加入流程的清晰入口。
7. 面试任务缺少安排面试入口，面试官可见范围需要收敛到本人。
8. 经理/负责人需要看到岗位进展、候选人归属、绩效和卡点的试点提示。
9. dev 环境需要四类角色试点账号，避免真实试用卡在账号准备。

## 2. 目标口径

### 2.1 Admin Users

管理员用户治理页的最小闭环口径统一为：

- 可列出账号
- 可创建试点账号
- 可编辑姓名 / 角色 / 启停状态
- 可重置密码
- 但它仍是 `demo-only` 账号治理壳层，不是完整 IAM

### 2.2 Candidate List

候选人列表页统一为：

- 上传后真实写入 Java rebuild PostgreSQL dev 数据库（当前为同步写入候选人记录，简历 JSON 暂以 `{}` 占位，尚未接真实异步解析链路）
- “已解析候选人”指标当前等于已上传候选人数量，不代表简历内容已完成结构化解析
- 页面不再暗示“只在前端临时显示”
- 空数据时引导去 `/upload`
- 已有候选人可选择有效岗位并加入 AI 初筛
- 加入成功后提示误推进可去候选人流程看板查看历史并纠正

### 2.3 Interview

面试任务统一为：

- 招聘专员、负责人、管理员可创建面试草稿
- 面试官只能看到自己的面试记录
- 没有面试时说明下一步：联系招聘专员确认是否安排到正确面试官账号
- 当前安排面试仍使用 ID 输入，后续升级为可搜索选择器

### 2.4 Manager Dashboard

经理/负责人工作台统一为：

- 显示团队看板提示
- 覆盖岗位进展、候选人归属、招聘专员绩效、流程卡点
- 明确 BI 口径按 `owner_hr_id` / `interviewer_id` 对齐

### 2.5 Agent

Agent 口径统一为：

- 整体定位为“进程内存态 + confirm-first”
- 会话列表/详情/消息发送属于已存在的 demo 会话壳层能力
- 写意图只生成 confirm-first 确认卡，不执行真实写操作
- 写意图继续受当前账号权限约束
- 面试官角色当前没有 AI 助手入口
- 该能力仍是演示壳层，不等于生产级会话中心、自动执行系统或可观测平台

### 2.6 Pipeline 边界

- `revert-lite` 写成 demo / legacy correction path
- `offer / onboarded / rejected` 写成当前重构壳层里的阶段记录边界
- 不再把它们包装成完整 Offer 审批、入职办理、淘汰治理闭环

### 2.7 Integration Demo

- 集成账号、扩展上下文、抓取任务属于 demo 壳层
- 当前是非真实第三方，不代表真实在线授权、真实抓取或真实回调
- 可以保留本地表结构目标口径，但不能包装成已完成第三方打通

### 2.8 试点账号

`dev` profile 自动初始化与原 Python 版 `backend/seed_dev.py` 对齐的本地演示账号：

- 招聘专员：`hr01@mvp.local` / `hr02@mvp.local` / `hr03@mvp.local`
- 招聘经理/负责人：`manager01@mvp.local` / `lead01@mvp.local`
- 面试官：`interviewer01@mvp.local`
- 管理员：`admin01@mvp.local`

统一密码为 `Zhipin2026`，用于本地试用，不用于真实用户小范围试点。

真实用户小范围试点使用 `pilot` profile：

- 不自动创建 demo 账号。
- 关闭公开注册，由管理员创建真实试点账号。
- 启动前校验 JWT、数据库密码、CORS、上传目录和本地演示账号残留。
- 首次管理员只通过一次性 bootstrap 环境变量创建，之后删除环境变量。

### 2.9 备份与健康检查

- `/api/v1/health` 必须返回应用和数据库状态；数据库不可用时返回 `503`。
- 试点备份必须同时包含 PostgreSQL dump 和上传文件。
- 恢复默认 dry-run，必须显式确认后才动数据。

## 3. 非目标

- 不把 demo 壳层升级为完整账号中心
- 不把 Agent 演示壳层升级为生产 observability 或真实自动写操作
- 不把集成 demo 壳层升级为真实第三方授权
- 不承诺完整 Offer / Onboard / Reject 业务治理已经完成
- 不承诺生产上线；本轮只判断小范围产品试点可用性
- 不做字段级加密实现；Java rebuild 当前不能声称 `FIELD_ENCRYPTION_KEY` 生效

## 4. 推荐对外表述

- `管理员用户治理最小闭环已可联调`
- `候选人上传后会真实写入 Java rebuild PostgreSQL dev 数据库（当前同步写入，简历 JSON 暂为占位，尚未接真实解析链路）`
- `候选人可加入岗位流程，误推进可去流程看板查看历史并纠正`
- `招聘专员、负责人、管理员可安排面试草稿；面试官只看本人面试`
- `招聘专员 BI 按自己负责范围统计，负责人/管理员当前按全局范围查看（demo 阶段未按团队细分）`
- `真实试点使用 pilot profile，dev demo 账号只用于本地演示`
- `健康检查返回数据库状态，数据库不可用时返回 503`
- `AI 助手会话列表/详情/消息发送已具备 confirm-first 演示壳层`
- `revert-lite 仅用于 demo / legacy correction`
- `Offer / Onboard / Reject 当前只表示阶段记录边界`

## 5. 验收标准

- 页面文案、README 与说明文档不再互相打架。
- 前端测试覆盖上传入口、候选人加入流程、经理团队看板提示、安排面试入口。
- 后端测试覆盖招聘专员 BI 范围、经理/管理员全局范围（demo 阶段未按团队细分）、面试官本人可见范围、安排面试接口。
- 后端测试覆盖 pilot 启动护栏、公开注册关闭、bootstrap 管理员和健康检查数据库状态。
- 脚本 dry-run 覆盖备份和恢复计划输出。
- 文档里不再把 AI 助手写成生产级会话中心、真实自动写操作或完整审计平台。
- 最终结论只能区分技术可运行、小范围产品试点可用、生产上线三类，不直接承诺生产上线。
