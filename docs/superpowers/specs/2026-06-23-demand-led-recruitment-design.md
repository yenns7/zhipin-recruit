# 招聘需求主线改版设计

## 背景

试用反馈集中在三个问题：候选人如何绑定需求、工作台数字为什么不能点击下钻、流程中的候选人能否切换招聘需求。根因是当前系统把“岗位”放在主线，把“用人需求”做成依附于岗位的记录；真实业务里用户先有“我要招人”的需求，再需要 JD/岗位画像来匹配候选人。

## 设计原则

- 招聘需求是业务主线：OA 或 HR 手工创建的是一次真实招人任务。
- 岗位/JD 是需求下的匹配画像：用于解析、匹配和流程统计，不要求用户先理解系统内的岗位对象。
- 候选人动作统一围绕需求表达：加入该需求流程、查看该需求流程、转入其他招聘需求。
- 工作台数字必须能落到可处理列表，避免只展示总数。

## 本期范围

本期不接 OA，不做数据库大迁移。使用现有 `jobs` 表继续保存岗位画像，使用现有 `recruitment_demands.job_id` 关联画像。

本期改动：

- 新建招聘需求时允许直接填写招聘岗位和岗位要求，后端自动创建岗位画像并关联需求。
- 保留“复用已有岗位画像”能力，但作为高级选项，不再作为创建需求的第一入口。
- 需求卡片提供“匹配候选人”和“查看该需求流程”两个主动作。
- 候选人匹配、简历库、流程页面的按钮和提示从“岗位流程”收敛为“需求流程”。
- 工作台关键数字和待办跳转到带筛选条件的候选人流程或面试任务。
- 流程页面提供“转入其他招聘需求”的用户入口和提示；后端迁移动作可以后续单独实现，本期先完成入口和产品语义收敛。

## 用户流程

1. HR 进入“招聘管理 → 用人需求”。
2. 点击新建招聘需求，填写招聘岗位、用人部门、人数、优先级、期望完成时间、岗位职责/任职要求。
3. 如果已有相似岗位，HR 可展开“复用已有岗位画像”，选择一个已有画像。
4. 创建后系统生成需求，并自动关联一个岗位画像。
5. 需求卡片点击“匹配候选人”，进入该需求的候选人匹配页。
6. 在匹配页点击“加入该需求流程”，候选人进入该需求的待筛选阶段。
7. 工作台点击阶段数字，直接进入对应需求/阶段列表。
8. 如果候选人更适合其他需求，HR 在流程详情里点击“转入其他招聘需求”，选择目标需求并填写原因。

## 文案约定

- 对业务用户展示：招聘需求、需求流程、岗位画像、复用已有岗位画像。
- 避免在主操作里使用：关联岗位、绑定岗位、岗位流程。
- 保留“招聘岗位”作为导航标签，但页面解释为“岗位画像/JD 管理”。

## 验收标准

- 用户可以不先创建岗位，直接创建招聘需求。
- 创建需求后，后端返回 `job_id`，匹配和流程仍能基于该 ID 正常工作。
- “关联岗位”文案不再出现在用人需求创建主表单。
- 需求卡片能直接进入匹配和流程。
- 工作台阶段数字可点击并带上阶段筛选。
- 流程详情出现“转入其他招聘需求”入口，并说明会保留历史和原因。
- README、RUNNING、PRD、BI、SDD 同步说明新口径。
