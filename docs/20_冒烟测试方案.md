# 智聘系统全功能冒烟测试方案

> **版本**: v1.0
> **日期**: 2026-07-09
> **适用范围**: Java Spring Boot 3 + React 18 重构版（`rebuild/`）
> **目标**: 验证系统「全功能可用 + 异常正常捕捉 + 不影响其他功能」，作为试点前/上线前的快速回归基线。

---

## 0. 背景与定位

### 0.1 为什么需要冒烟测试

智聘重构版已具备约 20 个业务模块、50+ 个 REST 端点，前后端均有各自的单测/组件测试，但缺少**跨模块聚合的冒烟回归**。后果是：

- 某次改动可能让「岗位画像」正常但「候选人流程」接口 500，而单测不会暴露跨模块连带影响。
- 异常处理链（`GlobalExceptionHandler` -> `ApiResponse` 信封 -> 前端 `ApiError`）一旦在某个模块退化，用户看到的就是白屏或原始堆栈，而非结构化提示。
- RBAC 边界（招聘专员不能看团队 BI、面试官不能进 AI 助手）退化后，单测按模块隔离无法发现权限越权。

冒烟测试专门补这一层：**以最小用例集，快速确认全链路主干可用、异常被正确兜底、模块间互不污染**。

### 0.2 冒烟测试与现有测试的关系

| 测试层 | 现状 | 作用 | 与冒烟测试关系 |
|--------|------|------|---------------|
| 后端 per-module 单测 | 31 个测试类，H2 内存库 | 验证单个 Controller 的字段/状态码 | 冒烟测试在其上做**跨模块聚合 + 异常隔离** |
| 前端 vitest 组件测试 | ~50 个 `.test.mjs` / `.test.tsx` | 验证组件渲染与交互 | 冒烟测试在其上做**角色路由可达 + 错误边界** |
| 端到端（E2E） | 暂无 | 真实服务 + 真实浏览器 | 冒烟测试**不替代** E2E，但能在 CI 中以低成本覆盖主干 |

冒烟测试不追求覆盖每个分支，而是保证「主干通路 + 异常兜底 + 权限边界」三类不变量。

### 0.3 三层判断口径（对齐 AGENTS.md）

本方案区分三个层次，避免「冒烟通过 = 可上线」的误判：

- **技术可运行**：冒烟测试全绿 = 主干接口可达、异常结构化、权限边界正确。**不等于可上线。**
- **产品可试用**：不同角色能完成关键路径，空数据/误操作有引导--需补充角色视角验收（见 §6）。
- **生产可上线**：需安全/备份/合规/审计/运维保障--超出冒烟测试范围，见 `docs/17`。

## 1. 系统架构与冒烟测试切入点

### 1.1 后端关键不变量

冒烟测试围绕以下四条不变量设计，任何一条被破坏都应让冒烟失败：

1. **统一信封**：所有 REST 端点返回 `ApiResponse<T>` = `{code, message, data, timestamp}`，前端 `request<T>()` 统一解包 `.data`。
2. **全局兜底**：`GlobalExceptionHandler`（`@RestControllerAdvice`）捕获 `AuthException`->对应状态码、`AccessDeniedException`->403、`MethodArgumentNotValidException`->400+字段明细、`IllegalArgumentException`->400、兜底 `Exception`->500。
3. **RBAC 分层**：`WebSecurityConfig` 在 URL 级放行 `/auth/**`、`/health`、swagger；`/admin/**` 要求 `ROLE_ADMIN`；其余需认证。部分端点在方法级用 `@PreAuthorize` 收紧（BI staff/job-funnel 要求 manager+，admin users/audit-logs/ai-architecture 要求 admin，interview schedule 要求 recruiter+，agent chat 仅 recruiter/manager/admin）。
4. **错误隔离**：一个模块抛错（如 Jobs get 不存在 ID 返回 400）不得影响其他模块（如 BI overview 仍 200）。模块间通过独立 Repository 访问，无共享可变状态。

### 1.2 前端关键不变量

1. **角色路由守卫**：`RequireAuth` + `RequireRole` 拦截未认证/越权路由，面试官进 `/agent` 会重定向回默认路由。
2. **错误边界防白屏**：`ErrorBoundary` 捕获子组件抛错（含懒加载 chunk 失败）-> 显示「页面加载出错」+ 刷新按钮，而非整站白屏。
3. **401 集中处理**：`api.ts` 的 `request()` 在 401 时调用注册的 `unauthorizedHandler`，清 token + 跳登录，各页面无需各自处理。
4. **空数据引导**：候选人/岗位/面试等列表为空时，提供「去上传」「去新建」等下一步入口，而非裸空列表。

### 1.3 冒烟切入点

```
┌─────────────────────────────────────────────────────────────┐
│  后端冒烟 SmokeTest.java  (H2 内存库 @SpringBootTest)         │
│  ├─ 20 模块 @Nested：正常 200 / 异常结构化 / RBAC 边界        │
│  └─ ErrorIsolation @Nested：模块间互不污染 + 全局兜底         │
└──────────────────────────┬──────────────────────────────────┘
                           │ 同一 ApiResponse 契约
┌──────────────────────────▼──────────────────────────────────┐
│  前端冒烟 SmokeRoutes.test.tsx  (vitest + jsdom)             │
│  ├─ 4 角色路由可达（mock API 空数组，页面不崩溃）             │
│  ├─ 空数据引导入口可见                                        │
│  ├─ ErrorBoundary 捕获 -> 不白屏                              │
│  └─ 401 集中处理 -> token 清除                                 │
└─────────────────────────────────────────────────────────────┘
```

## 2. 后端 API 冒烟测试设计

### 2.1 测试基座

- **类位置**：`rebuild/backend-java/src/test/java/com/hireinsight/smoke/SmokeTest.java`
- **Profile**：`@ActiveProfiles("test")`，使用 H2 内存库（`jdbc:h2:mem:testdb;MODE=PostgreSQL`），无需本机 PostgreSQL。
- **JWT**：`@TestPropertySource(properties = {"app.jwt.secret=0123456789abcdef0123456789abcdef"})`，复用现有测试模式。
- **Token 生成**：复用 `JwtTokenProvider.createToken(userId, role)` + `DemoAuthSessionService.activate(token)`，与 `JobControllerTest` / `BiControllerTest` 完全一致。
- **四角色 fixture**：`setUp()` 中一次性创建 admin / manager / recruiter / interviewer 四个用户并生成 token，各 `@Nested` 组共享。

```java
// 复用现有模式，与 JobControllerTest.bearerToken() 一致
private String token(User user) {
    String t = jwtTokenProvider.createToken(user.getId(), user.getRole());
    demoAuthSessionService.activate(t);
    return t;
}
```

### 2.2 模块覆盖矩阵

下表是冒烟测试的完整覆盖范围。**正常路径**验证功能可用，**异常路径**验证异常被结构化捕捉，**RBAC 边界**验证权限不越权。「-」表示该模块在该维度无显式用例（不代表不测，而是该维度由正常/异常路径间接覆盖）。

| # | 模块 | 端点 | 正常路径（200） | 异常路径（结构化错误） | RBAC 边界 |
|---|------|------|----------------|----------------------|----------|
| 1 | Health | `GET /health` | status=UP, database=UP | - | 公开，无需认证 |
| 2 | Auth | `POST /auth/login` | 成功 -> 返回 token+role+name | 错误密码 -> 401 envelope `{code:401,message:"Invalid credentials"}` | `GET /users/me` 无 token -> 401 |
| 3 | Users | `GET /users/me` | 返回当前用户 id/email/role | - | - |
| 4 | Jobs | list / create / get / close / restore | create -> 201 `{id}`；close -> status=closed；restore -> status=active | create 空标题 -> 400 + 字段明细 `{title:"must not be blank"}`；get 不存在 ID -> 400 `{code:400,message:"Job not found: 9999"}` | 无 token -> 401 |
| 5 | Candidates | list / get / owner-options | list 专员看自己、经理看全部；owner-options 返回 recruiter+manager 列表 | get 不存在 -> 400 `{code:400,message:"Candidate not found: 9999"}` | 无 token -> 401 |
| 6 | Pipeline | move / board / history | move -> `{id, stage}`；board -> `{jobId, stages:{...}}` | move 非法 stage -> 400 + 合法 stage 清单 `{code:400,message:"Invalid stage: xxx. Valid: [pending,ai_screen,...]}"}` | 无 token -> 401 |
| 7 | Match | `POST /match` / `GET /match/jobs/{jobId}/preview` | match -> 排序后的 MatchResponse 列表 | match 不存在 jobId -> 404 `{code:404,message:"Job not found: 9999"}` | 无 token -> 401 |
| 8 | Interview | list / interviewers / assignments / guide | list 返回面试记录；interviewers 返回启用面试官 | - | schedule 无 token -> 401 |
| 9 | BI | overview / staff / job / funnel / channel-quality / ... | overview 所有角色 200；funnel 返回周期指标 | staff 不存在 hrId -> 404 `{code:404,...}` | **recruiter -> staff -> 403**；**recruiter -> job-funnel -> 403** |
| 10 | Resume | `GET /resumes/search` / `POST /resumes/upload` | search 返回候选人列表；upload(multipart) -> `{candidateIds:[...]}` | - | upload 无 token -> 401 |
| 11 | Notifications | list / unread-count / read / read-all | list 返回 `{notifications, total, unreadCount}`；unread-count 返回数字 | - | 无 token -> 401；list 只返回当前 userId 的通知 |
| 12 | Talent Maps | list / create / get / companies / people | create -> 200；get 返回 `{map, companies, people}` | - | 无 token -> 401 |
| 13 | Demands | list / get / create / close / restore / downgrade | create -> 200；close -> status=closed；restore -> status=open | - | 无 token -> 401 |
| 14 | Agent | conversations(list/create/get/patch/delete) / tools / call-logs | conversations list 返回数组；tools 返回工具清单 | - | **interviewer -> /agent/chat -> 403**（URL 级 `/api/v1/admin/**` 或方法级限制） |
| 15 | Admin Users | `GET /admin/users` / `POST /admin/users` / reset-password | list 返回用户数组 | - | **recruiter -> list -> 403**；**recruiter -> create -> 403** |
| 16 | Audit Logs | `GET /admin/audit-logs` | 返回日志列表 | - | **recruiter -> 403** |
| 17 | AI Architecture | `GET /admin/ai-architecture` | 返回架构概览 | - | **recruiter -> 403** |
| 18 | Boss | status / login / jobs / candidates/inbox | status 返回 `{installed, demoMode}` | boss-cli 未安装时 status 仍 200（降级而非崩溃） | 无 token -> 401 |
| 19 | Offer | withdraw / approve / create | create -> 200 | - | 无 token -> 401 |
| 20 | Disposition | list / create | list 返回处置记录 | - | 无 token -> 401 |

### 2.3 异常隔离验证（「不影响其他功能」的核心）

单独 `@Nested class ErrorIsolation`，专门验证「一个模块的错误不阻断其他模块」：

| 用例 | 验证点 | 预期 |
|------|--------|------|
| `jobsErrorDoesNotBlockBi` | 先请求 `GET /jobs/9999`（400），再请求 `GET /bi/overview` | 第二个请求仍 200，BI 数据正常 |
| `pipelineInvalidStageDoesNotBlockCandidates` | 先 `POST /pipeline/move`（非法 stage -> 400），再 `GET /candidates` | 第二个请求仍 200 |
| `matchNotFoundDoesNotBlockNotifications` | 先 `POST /match`（不存在 jobId -> 404），再 `GET /notifications` | 第二个请求仍 200 |
| `uncaughtExceptionReturnsEnvelope` | 触发未捕获异常（如构造场景使 `GlobalExceptionHandler.handleUnknown` 生效） | 返回 500 envelope `{code:500,message:"Internal server error"}`，**不泄露堆栈** |
| `validationErrorReturnsFieldMap` | `POST /jobs` 空标题 | 400 `{code:400,message:"Validation failed",data:{title:"must not be blank"}}` |
| `illegalArgumentReturns400` | `GET /jobs/9999` | 400 `{code:400,message:"Job not found: 9999"}` |
| `accessDeniedReturns403` | recruiter 调 `GET /admin/users` | 403 `{code:403,message:"Forbidden"}` |

### 2.4 每个模块的通过标准

统一断言模式（以 Jobs 为例）：

```java
@Test
void createJobReturns201() throws Exception {
    mockMvc.perform(post("/api/v1/jobs")
            .header("Authorization", "Bearer " + recruiterToken)
            .contentType(MediaType.APPLICATION_JSON)
            .content("{\"title\":\"后端工程师\",\"jdText\":\"负责核心业务\"}"))
        .andExpect(status().isCreated())
        .andExpect(jsonPath("$.code").value(201))
        .andExpect(jsonPath("$.data.id").isNumber());
}

@Test
void createJobBlankTitleReturns400WithFieldMap() throws Exception {
    mockMvc.perform(post("/api/v1/jobs")
            .header("Authorization", "Bearer " + recruiterToken)
            .contentType(MediaType.APPLICATION_JSON)
            .content("{\"title\":\"\",\"jdText\":\"x\"}"))
        .andExpect(status().isBadRequest())
        .andExpect(jsonPath("$.code").value(400))
        .andExpect(jsonPath("$.message").value("Validation failed"))
        .andExpect(jsonPath("$.data.title").exists());
}

@Test
void getJobWithoutTokenReturns401() throws Exception {
    mockMvc.perform(get("/api/v1/jobs"))
        .andExpect(status().isUnauthorized());
}
```

每个模块至少包含：1 个正常路径 + 1 个异常路径（如适用）+ 1 个 RBAC 边界（如适用）。

## 4. 一键运行脚本设计

### 4.1 脚本

**文件**：`scripts/smoke-test.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

ROOT="$(cd "$(dirname "$0")/.." && pwd)"
FAILED=0

echo "=========================================="
echo "  智聘系统冒烟测试"
echo "=========================================="

# ---- 后端冒烟（H2 内存库，无需 PostgreSQL）----
echo ""
echo "[1/2] 后端 API 冒烟测试 (H2 内存库)..."
cd "$ROOT/rebuild/backend-java"
if mvn test -Dtest=SmokeTest -q; then
  echo "  ✅ 后端冒烟通过"
else
  echo "  ❌ 后端冒烟失败"
  FAILED=1
fi

# ---- 前端冒烟 ----
echo ""
echo "[2/2] 前端页面冒烟测试 (vitest)..."
cd "$ROOT/frontend"
if npx vitest run src/smoke/SmokeRoutes.test.tsx; then
  echo "  ✅ 前端冒烟通过"
else
  echo "  ❌ 前端冒烟失败"
  FAILED=1
fi

# ---- 汇总 ----
echo ""
echo "=========================================="
if [ "$FAILED" -eq 0 ]; then
  echo "  ✅ 全部冒烟测试通过"
  exit 0
else
  echo "  ❌ 存在失败，请检查上方输出"
  exit 1
fi
```

## 5. 通过标准与失败处理

### 5.1 通过标准

冒烟测试「全绿」需同时满足：

1. **后端 20 模块**：每个模块的正常路径返回正确状态码 + ApiResponse 信封结构正确。
2. **后端异常路径**：结构化错误响应（400/401/403/404/500）均走 `ApiResponse` 信封，`message` 人类可读，校验错误有字段明细。
3. **后端异常隔离**：`ErrorIsolation` 组全部通过--一个模块的错误不影响其他模块。
4. **后端 RBAC**：所有权限边界用例返回预期状态码（无 token -> 401，越权 -> 403）。
5. **前端路由可达**：4 个角色的主路由均可渲染且不崩溃。
6. **前端错误边界**：`ErrorBoundary` 捕获抛错，不白屏。
7. **前端 401 处理**：401 触发 `unauthorizedHandler`，token 清除。

### 5.2 失败处理流程

```
冒烟失败
   │
   ├─ 后端某模块正常路径失败 -> 该模块功能不可用，阻塞试点
   │     └─ 修复后重跑该模块 @Nested 组验证
   │
   ├─ 后端异常路径返回非结构化（如裸堆栈/HTML）-> GlobalExceptionHandler 退化，阻塞
   │     └─ 检查 @RestControllerAdvice 是否被覆盖、是否有端点直接抛未处理异常
   │
   ├─ 后端异常隔离失败 -> 模块间存在共享可变状态/事务泄漏，阻塞
   │     └─ 检查是否有静态可变字段、共享缓存未隔离
   │
   ├─ 后端 RBAC 边界失败 -> 权限越权，阻塞
   │     └─ 检查 WebSecurityConfig / @PreAuthorize 是否被改动
   │
   ├─ 前端路由崩溃 -> 页面渲染异常，阻塞
   │     └─ 检查该页面是否缺少空数据兜底 / 未捕获 Promise rejection
   │
   └─ 前端 ErrorBoundary 未生效 -> 整站白屏风险，阻塞
         └─ 检查 ErrorBoundary 是否包裹在路由树外层
```

### 5.3 冒烟通过 ≠ 可上线

冒烟全绿仅代表「技术可运行」。是否可试点/上线，仍需按 `AGENTS.md` 的试点判断规则完成：

- **角色视角审查**：分别从招聘专员/经理/面试官/管理员走关键路径。
- **缺口入口审查**：无岗位/候选人/面试官/账号时是否有清楚提示和下一步。
- **反向操作审查**：关闭后能否恢复、推进后能否撤回、负责人能否调整。
- **数据归属审查**：候选人负责人/推进人/反馈人/岗位归属/BI 口径是否一致。
- **文档和限制审查**：运行方式/账号密码/已知限制是否写清楚。

## 7. 已知限制与后续演进

### 7.1 当前方案不覆盖

- **真实 LLM 调用**：Agent chat / 简历解析走 stub/demo 路径，不验证 LLM 真实可用性（需单独集成测试 + API Key）。
- **boss-cli 真实集成**：Boss 模块在 demo 模式下验证降级，不验证真实 BOSS 直聘拉取。
- **文件上传真实解析**：`POST /resumes/upload` 验证接口可达和响应结构，不验证 pdfplumber/python-docx 解析链路（该链路在 Python base_agent 侧）。
- **并发/性能**：冒烟不验证高并发下的线程安全与性能基线。
- **数据库迁移**：冒烟用 H2 `create-drop`，不验证 Flyway/DDL 在真实 PostgreSQL 上的迁移正确性。

### 7.2 后续演进建议

| 阶段 | 补充 | 目的 |
|------|------|------|
| 试点前 | 补充 E2E（Playwright/Cypress） | 覆盖真实浏览器 + 真实服务的完整用户路径 |
| 试点中 | 接入 APM/日志监控 | 捕获冒烟无法覆盖的运行时异常 |
| 上线前 | 补充真实 PostgreSQL 集成测试 | 验证 H2 与 PG 的方言差异（如 JSONB、序列） |
| 上线后 | 冒烟纳入 CI 门禁 | 每次 PR 合并前自动运行，阻断退化 |
