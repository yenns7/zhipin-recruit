# 验收与试点说明

> **版本**: 1.0.0 | **文档状态**: 初版 | **适用范围**: 内部技术试点（pilot）
>
> 本文档用于指导验收团队完成试点前的功能验证和风险评估。验收时请按角色逐条过冒烟清单。

## 三层判定结论

### 技术可运行：是

- 前端 `npm run dev` 正常启动，`npm run build` 成功
- 后端 `mvn spring-boot:run` 正常启动（dev profile）
- typecheck 0 错误
- 后端 285 个 @Test 全绿（H2 内存库）
- 前端 53 个 vitest 测试 + 52 个契约测试全绿
- 全部 115 个可调用端点已验证通过
- 健康检查 `/api/v1/health` 返回 UP

### 产品可试用：部分

四角色可以走通主要路径，但存在以下缺口：

**招聘专员** 可以上传简历、管理候选人、推进流程、安排面试。但：简历解析无 LLM key 时 mock、面试安排表单填 ID（无搜索选择器）、BI 只能看自己范围的数据。

**招聘经理** 可以看到团队数据、跨岗位漏斗。但：BI 专员归因按 owner_hr_id，经理/管理员看全局（未按团队细分）；没有"我的团队"概念。

**面试官** 可以看到被分配的面试任务、提交反馈。但：首次登录看到的是空列表，没有引导提示。

**管理员** 可以管理用户、看审计日志。但：系统治理页面（参数切换/模型状态）是 demo 壳层，没有实际效果。

空数据/误操作的处理：岗位列表空时有引导，简历库空时有上传入口。但误关闭岗位可以恢复，误淘汰候选人可以用 pipeline 修正。面试官列表空时没有"联系管理员添加"的提示。

### 生产可上线：否

以下条件不满足：

- 没有生产级监控和告警
- 没有灾备演练记录
- BOSS 直聘未接入真实数据
- AI 助手写操作只出确认卡
- 没有数据合规/隐私审查
- 面试安排、BI 范围等功能存在已知限制
- Flyway 迁移脚本编号不连续
- 三个后端接口未实现（updateCandidateProfile、clarifyJob）

## 已知限制完整清单

1. **BOSS demo-stub 模式**（BOSS_DEMO_MODE=true）。所有 BOSS 端点返回 in-memory 静态样例数据，不连接真实 BOSS 直聘。真实 boss-cli 集成仅在 Flask 旧版。
2. **AI 无 key 降级**（LLM_KEY 为空）。AI 面试出题/评分、简历解析、AI 助手对话全部降级为 mock 或规则。这不算 bug，但验收时看到的 AI 数据是假的。
3. **Flyway 迁移脚本跳号**。缺 V1-V4、V6-V8。现有编号：V5、V9-V18。迁移回滚时不要依赖编号连续性。
4. **简历解析依赖 LLM key**。无 key 时返回 mock 占位数据，不真实抽取技能/教育经历。
5. **面试安排表单填 ID**。候选人/岗位/面试官用 ID 输入框，没有搜索选择器。产品体验差但能用。
6. **BI 专员归因按 owner_hr_id**。经理/管理员看全局数据，未按团队细分。demo 阶段没有团队归属模型。
7. **没有生产级监控/灾备演练**。只有 `/api/v1/health` 和备份脚本。无告警、APM、恢复演练。
8. **通知和处置响应字段是 snake_case**。Java 手写 Map 导致。前端已适配，但风格不统一。
9. **三个前端方法标记未实现**。updateCandidateProfile、clarifyJob 等（详见 03_接口文档.md）。后端尚未实现，调用会 404。
10. **系统治理是 demo 壳层**。参数切换和模型状态切换没有真实效果。
11. **AI 助手写操作只出 confirm-first 确认卡**。不真实执行写操作。
12. **登录限流 5 次/60 秒**。连续输错密码会被短暂锁定。
13. **上传文件默认存 /tmp**。生产部署必须改 UPLOAD_FOLDER。
14. **pilot profile 首次启动需要 bootstrap 管理员**。临时设置 PILOT_BOOTSTRAP_ADMIN_EMAIL/PASSWORD，首次登录后需删除并重启。

## 风险评级汇总

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| BOSS 数据为 demo-stub，重启丢失 | 中 | 高 | 试点前告知用户"BOSS 数据仅供演示" |
| AI 无 LLM key 时返回 mock 数据 | 低 | 中 | 试点准备时配置 LLM key 即可避免 |
| 面试安排需手动填 ID（无选择器） | 中 | 高 | 当前可接受，已列入下一阶段优化 |
| 未实现的 3 个后端接口调用会 404 | 低 | 低 | 前端已标注，试点用户不会用到 |
| Flyway 迁移脚本编号不连续 | 低 | 低 | 不影响运行，回滚时注意 |
| 无生产级监控/告警 | 高 | 中 | 试点期间加强手动巡检 |
| 无灾备恢复演练 | 高 | 低 | 试点数据量小，备份脚本可用 |

**总体风险等级**：中。可以开始小范围产品试用（< 10 人），但不应承载真实业务数据。
